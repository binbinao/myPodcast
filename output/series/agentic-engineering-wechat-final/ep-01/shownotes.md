# 什么是 Agentic Engineering？一个故事讲透

> 什么是 Agentic Engineering？一个故事讲透 · 第 1 集

听：series/agentic-engineering-wechat-final/ep-01/episode.mp3 · 时长 9 分 31 秒 · 2026-09-21 · 主播：小搭

**[host]** 凌晨三点十二分，你的手机震了一下。你迷迷糊糊摸到手机，屏幕上是 GitHub 发来的邮件，说你维护的那个八百星小项目，有人提了个新 issue，希望支持 Markdown 表格转 PDF。

**[guest]** 你叹了口气，正准备爬起来干活。点开一看，PR 已经提了，测试已经跑了，代码也已经 review 过了。

**[host]** 你揉揉眼睛，以为自己在做梦。再往下翻，commit message 写得工工整整，测试用例一个没少，PR 描述里还特意谢了提交者。

**[guest]** 你躺回床上，翻了个身继续睡。第二天早上八点，泡了杯咖啡，点了一下 Approve。

**[host]** 这样的场景，二零二六年已经在真实发生。那它是怎么来的？

**[guest]** 说来听听，从一句需求到 PR 全绿，中间到底是谁在干活？

**[host]** 过去三年，第一波是 Copilot 自动补全。你写一行代码，它帮你补半行，像个 pair programming 的同事。但它记不住你项目的规矩。

**[host]** 第二波是 ChatGPT 对话。你问它答，像个资深同事。你让它写函数它就写函数，让它改 bug 它就改 bug。可你一关掉对话，它就忘了你是谁。

**[guest]** 那卡在哪儿呢？两个波次，各有各的硬伤。Copilot 记不住你项目里的编码规范。ChatGPT 一关窗口，思路就断了，它能写代码，却不会自己 push，能跑测试，却不会自己提 PR。

**[host]** 第三波，就是 Agentic Engineering。它补的，正是你刚说的那些窟窿。所以现在的 Agent，更像个助手，还没到员工的份上。助手在你召唤的时候才存在。员工不一样，员工有自己的工位，有自己的工具，也认自己那套流程。

**[guest]** 那把 Agentic Engineering 说成一句话，就是把这些东西一样一样给它配齐？

**[host]** 想象你开了家公司，来了个新员工，你总得给他配点什么。

**[host]** 第一件，一本工作手册，叫 Agent Profile。里面写清楚几条规矩。我们用 CommonJS，别用 ES Module。测试必须跑 npm test。commit message 要用 feat: 前缀。Agent 永远记得这些，不用你每次都重复。

**[guest]** 规矩立住了，可它手里的工具呢？

**[host]** 第二件，一个工具箱，叫 Skills。团队里有个老司机特别擅长处理 PDF，你把他的绝活沉淀成一个技能包。下次遇到 PDF 的事，Agent 直接调这个技能，不用从零学起。

**[guest]** 那它光在对话框里打转也不行吧，总得能碰到外面的世界。

**[host]** 所以第三件，一套外接设备，MCP。以前 Agent 只能在你给它打电话时工作。现在它自己能操作 GitHub，能跑命令行，能控制浏览器。就像手机，从只能打电话，变成能插 USB-C 接各种设备。

**[guest]** 它自己跑起来，你不怕它乱来？

**[host]** 所以要第四件，几道安检门，Hooks。机场过安检，值机前查一次，登机前再查一次。Agent 写完代码要 commit，先过 lint。准备 push，先跑测试。全通过才能往下走。

**[guest]** 那要是没人盯着，它是不是就停了？

**[host]** 第五件，一个二十四小时值班的员工，Loops。以前你叫它才动，现在它七天二十四小时盯着。有人提 issue，自动处理。有人开 PR，自动 review。不用你催，它自己干活。

**[guest]** 五件套拼起来，就是一台自动开发机。配齐了，Agent 就能上岗。那它能帮你干哪些活？

**[host]** 第一，coder，写代码的。替代程度五颗星。它自己读 issue、拆解任务、写代码、改 bug、跑测试、提 commit。

**[host]** 有个真实案例。用户提了句希望支持表格转 PDF，Agent 自己分析需求，自己写 src/table.js，自己补测试，自己跑 npm test 全绿，自己提了 PR。全程二十一分钟。

**[guest]** 二十一分钟。那审代码呢？

**[host]** 第二，reviewer，审代码的。四颗星。它自动扫 diff，列修改意见。哪里不规范，哪里的测试没覆盖，哪里埋着安全风险，比人工审得还细。而且它不会累，二十四小时干活也不抱怨。

**[guest]** 写测试和写文档呢，也能替？

**[host]** 第三，tester，写测试的。四颗星。边界情况容易漏，Agent 自动补测试用例。空文件、超大文件、非正常输入，它能帮你想到一堆角落里的场景。

**[host]** 第四，docs-writer，写文档的。三颗星。每次发版都要更新 README、CHANGELOG，Agent 自动帮你写。commit message 里的 feat: xxx，它自动抽出来整理成 changelog。

**[guest]** 那我们以后就负责点批准？

**[host]** 差不多。以前是你写代码，AI 帮你补。现在是 AI 写代码，你只负责点批准。

**[guest]** 可这里有个关键问题。AI 能写代码了，那谁来告诉它写什么？

**[host]** 你会发现一个有意思的现象。AI 很擅长执行，但不太擅长理解。你让它把表格转成 PDF，它能写。可它不知道你为什么要转 PDF。

**[host]** 是给客户发报告用，还是内部留档？表格里有哪些列？哪些是财务数据，哪些是用户列表？转成什么样才算对，要不要分页，要不要页眉？

**[guest]** 所以它知道怎么做，却不知道为什么做。

**[host]** 对，这就回到最根本的问题。谁能先把业务讲清楚？

**[guest]** 那程序员这个角色，是不是要变了？

**[host]** 以前，程序员是翻译机，把产品经理的想法翻译成代码。以后，程序员是指挥官，把业务需求翻译成 AI 指令。

**[guest]** 那以后最值钱的能力是什么？

**[host]** 以前最稀缺的是会写代码的手。以后最稀缺的是懂业务的大脑。当你比产品经理更懂业务，当你比任何人都清楚这个功能为什么要做、做到什么程度、影响哪些流程，你就变成了不可替代的人。

**[host]** 你不需要亲手写代码，但你需要下达精准的指令。这就是 AI 时代程序员最大的机会。

**[guest]** 那具体从哪儿开始？

**[host]** 三个建议。第一，学业务，别只学技术。技术会过时，AI 会进化，但你对业务的理解，别人拿不走。你比产品经理更懂业务，你就是 AI 的翻译官，只有你能把业务需求准确传达给 AI。

**[host]** 第二，用起来。去装个 CodeBuddy，花半小时写一个 AGENT.md。不用搞多复杂，就写写你项目的规矩、你团队的规范。试试让 AI 自己跑一次 test，自己提一次 PR。

**[host]** 第三，把自己当成指挥官。以后问 AI 这个功能怎么实现之前，先问自己三遍为什么要做。想清楚了，再下达指令。

**[guest]** 我明白了。以前我先想怎么写，现在得先想清楚要什么。

**[host]** AI 时代，最值钱的是懂业务的大脑。去成为那个指挥官吧。

**[guest]** 别只当那个会敲键盘的人。要当那个知道为什么敲键盘的人。
